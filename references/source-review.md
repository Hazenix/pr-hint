# 源码模块审查

按用户指定或从主题推定的模块查源码、测试、配置和直接上下游。用户给了多个模块时按指定顺序逐轮处理，未指定顺序时从最贴近目标的模块开始。用户要求分步时，在聊天中给出当前模块的结果后等待继续。

先用实际调用链和运行条件核验候选，再按主流程对该候选定向查 Issue、PR 和 commit。候选成立前只读本地文件，贡献文档和架构文档用于理解约束。社区待办、标签、分支名和 roadmap 不用于决定查哪些代码。即使上一个模块已开始去重，下一个模块仍先查源码。找不到 Issue 时也核对 PR 和提交历史。

## 模块清单

在工作目录的 `./reference/PR_HINT_PROGRESS_<repo-slug>.md` 中，把 `## 当前模块清单` 放在文件标题之后、所有 `Round` 之前。记录仓库与远端、分支、基准提交、盘点时间，以及模块的名称、路径、职责、入口、测试位置和贡献边界。

- 开始深入源码前读取已有清单。核对仓库路径、远端、分支或提交和关键目录，清单仍适用时直接复用。
- 清单缺失、关键路径或模块边界已变，或用户要求刷新时，补做必要的结构盘点。部分过时就更新对应条目。
- 在当轮账本追加范围和清单复用或刷新依据。刷新时记录模块变化，历史轮次保留。
